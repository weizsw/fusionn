## 🎯 Design Decisions

### 1. Pipeline Placement
**Decision:** Style processor runs **after** DuoSubs merge, **before** file output.

**Rationale:**
- DuoSubs outputs complete ASS with all sections
- Styling must happen before copying to final destination
- Allows future processors to work with styled subtitles

### 2. Error Handling
**Decision:** Non-critical failures (invalid ASS) log warnings and skip styling.

**Rationale:**
- Don't fail the entire job for styling issues
- Users get merged subtitles even if styling fails
- Malformed ASS edge cases handled gracefully

### 3. Hot-Reload Support
**Decision:** Style config is part of the main `SubtitleConfig`, fully hot-reloadable.

**Rationale:**
- Consistent with other subtitle settings
- Users can tweak styles without restart
- Next merge job uses updated styles immediately

### 4. ASS Section Preservation
**Decision:** Only replace Script Info and V4+ Styles, preserve Events exactly.

**Rationale:**
- DuoSubs generates accurate timing and alignment
- Subtitle content and timing must remain unchanged
- Only visual appearance is modified

## 🚀 How It Works

1. **Webhook arrives** → Job enqueued to merge queue
2. **Analysis pipeline** → Detect and extract subtitles
3. **Merge pipeline** → Process through queue workers:
   - **ConversionProcessor**: Traditional → Simplified (if needed)
   - **MergerProcessor**: DuoSubs merge
   - **StyleProcessor**: Inject custom styles ← **New**
   - **OutputProcessor**: Copy to video directory
   - **NotificationProcessor**: Send Apprise notification
   - **CleanupProcessor**: Remove temp files
