# Design: Add Custom ASS Styling

**Change ID:** `add-custom-ass-styling`

## Problem Statement

DuoSubs generates merged ASS subtitles with default styling that may not be optimal for bilingual content. We need a way to customize the visual appearance of merged subtitles while preserving the subtitle content and timing.

## Design Goals

1. **Preserve subtitle content**: Never modify subtitle text or timing
2. **Configurable**: Allow users to customize fonts, colors, sizes via YAML
3. **Non-destructive**: Original merged file can be preserved if needed
4. **Extensible**: Easy to add more style options in the future
5. **Fail-safe**: Invalid configuration or ASS files should not crash the pipeline

## Solution Architecture

### Component Overview

```
MergerProcessor
    ↓
  merged.ass (DuoSubs default style)
    ↓
StyleProcessor (NEW)
    ↓
  merged.ass (Custom style injected)
    ↓
OutputProcessor
```

### ASS File Structure

An ASS subtitle file has three main sections:

1. **[Script Info]**: Metadata about the script
2. **[V4+ Styles]**: Visual style definitions
3. **[Events]**: The actual subtitle content with timing

**Our approach**: Replace sections 1 and 2, preserve section 3.

### Style Injection Algorithm

```go
func ProcessStyle(assFile string, config ASSStyleConfig) error {
    // 1. Read ASS file
    content := ReadFile(assFile)
    
    // 2. Parse into sections
    sections := ParseASS(content)
    
    // 3. Generate custom Script Info
    scriptInfo := GenerateScriptInfo()
    
    // 4. Generate custom V4+ Styles from config
    styles := GenerateStyles(config)
    
    // 5. Reconstruct ASS file
    newContent := scriptInfo + styles + sections.Events
    
    // 6. Write back to file
    WriteFile(assFile, newContent)
}
```

### ASS Style Format

ASS colors use BGR format (Blue-Green-Red) in hexadecimal:
- Format: `&HAABBGGRR`
- Example: `&H0010b8ff` = Alpha 00, Blue 10, Green b8, Red ff

**Style fields:**
```
Style: Name, Fontname, Fontsize, PrimaryColour, SecondaryColour, 
       OutlineColour, BackColour, Bold, Italic, Underline, StrikeOut, 
       ScaleX, ScaleY, Spacing, Angle, BorderStyle, Outline, Shadow, 
       Alignment, MarginL, MarginR, MarginV, Encoding
```

### Configuration Design

```yaml
subtitle:
  ass_style:
    enabled: true
    
    # Primary style (Chinese - larger, top line)

func GenerateStyle(name, font string, size int, color string, config ASSStyleConfig) string {
    bold := 0
    if config.Bold {
        bold = 1
    }
    
    return fmt.Sprintf(
        "Style: %s,%s,%d,%s,&H0000ffff,&H00000000,&H00000000,%d,0,0,0,90,100,0,0,1,%.1f,%.1f,2,10,10,%d,1\n",
        name, font, size, color, bold, config.Outline, config.Shadow, config.MarginV,
    )
}
```

### 3. ASS Parsing

```go
type ASSFile struct {
    ScriptInfo string
    Styles     string
    Events     string
}

func ParseASS(content string) (*ASSFile, error) {
    // Find section markers
    scriptInfoStart := strings.Index(content, "[Script Info]")
    stylesStart := strings.Index(content, "[V4+ Styles]")
    eventsStart := strings.Index(content, "[Events]")
    
    if eventsStart == -1 {
        return nil, fmt.Errorf("invalid ASS file: missing [Events] section")
    }
    
    // Extract sections
    return &ASSFile{
        ScriptInfo: content[:stylesStart],
        Styles:     content[stylesStart:eventsStart],
        Events:     content[eventsStart:],
    }, nil
}
```

### 4. Style Processor

```go
type StyleProcessor struct {
    config ASSStyleConfig
}

func (p *StyleProcessor) ShouldRun(pctx *ProcessingContext) bool {
    return p.config.Enabled && pctx.MergedSubPath != ""
}

func (p *StyleProcessor) Process(ctx context.Context, pctx *ProcessingContext) error {
    logger.Info("Injecting custom ASS styles")
    
    // Read merged ASS file
    content, err := os.ReadFile(pctx.MergedSubPath)
    if err != nil {
        return fmt.Errorf("failed to read ASS file: %w", err)
    }
    
    // Parse ASS
    parsed, err := ParseASS(string(content))
    if err != nil {
        logger.Warnf("Failed to parse ASS file, skipping styling: %v", err)
        return nil // Don't fail the job
    }
    
    // Generate custom styles
    scriptInfo := GenerateScriptInfo()
    styles := GenerateStyles(p.config)
    
    // Reconstruct ASS
    newContent := scriptInfo + styles + parsed.Events
    
    // Write back
    if err := os.WriteFile(pctx.MergedSubPath, []byte(newContent), 0644); err != nil {
        return fmt.Errorf("failed to write styled ASS: %w", err)
    }
    
    logger.Infof("✅ Custom styles injected: %s", pctx.MergedSubPath)
    return nil
}
```

## Trade-offs

### Approach 1: Modify in-place (CHOSEN)
**Pros:**
- Simple implementation
- No additional temp files
- Works with existing pipeline

**Cons:**
- Original DuoSubs style is lost
- Can't A/B test styles easily

### Approach 2: Create separate file
**Pros:**
- Preserves original
- Easy to compare

**Cons:**
- More disk usage
- User confusion (which file to use?)

### Decision: Approach 1
- Users can disable styling if they prefer DuoSubs defaults
- Preserving original adds complexity with little benefit

## Error Handling

### Invalid ASS Format
- **Detection**: Missing `[Events]` section
- **Action**: Log warning, skip styling, continue pipeline
- **Rationale**: Better to have unstyled subtitle than fail the entire job

### Invalid Config
- **Detection**: Font size <= 0, invalid color format
- **Action**: Validation error at startup
- **Rationale**: Fail fast, don't process with bad config

### Write Failure
- **Detection**: `os.WriteFile` returns error
- **Action**: Return error, fail the job
- **Rationale**: Styled file is incomplete, better to retry

## Open Questions

### Q: What if WenQuanYi Micro Hei is not installed on playback device?
**A**: Player will fallback to default font. Document font installation in `ASS_STYLING.md`.

### Q: Should we support multiple style presets?
**A**: Not in v1. Add in future if users request it.

### Q: Should we validate ASS after styling?
**A**: No. Trust our generation logic. Manual tests will catch issues.
